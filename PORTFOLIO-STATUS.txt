3. HOSTING
----------
Cloudflare WORKERS, not Cloudflare Pages. This matters:
  - Deploy is `npx wrangler deploy` after `npm run build`.
  - There is no dashboard "build output directory" field. The output directory
    lives in wrangler.jsonc.
  - It is an assets-only Worker: no `main` entrypoint, no server code.
  - URL shape is <worker-name>.<account-subdomain>.workers.dev
      worker name       = srijan-ratrey   (the `name` in wrangler.jsonc)
      account subdomain = sr5             (account-wide Cloudflare setting)
  - Pages projects get *.pages.dev. Workers do not. Don't mix them up.

wrangler.jsonc:
  name               srijan-ratrey
  compatibility_date 2026-08-04
  assets.directory   ./dist
  assets.not_found_handling  "404-page"   (serves dist/404.html)

Auto-deploy is wired: push to `main` -> production. Push any other branch ->
its own preview URL.

IMPORTANT: `site` in astro.config.mjs must always equal the deployed origin.
The RSS feed, the sitemap and every canonical tag are built from it. If it is
wrong, the build still succeeds and everything still looks fine — only the feed,
sitemap and canonicals are wrong. This value was wrong three times during setup
for exactly that reason. It is currently correct:
  site: 'https://srijan-ratrey.sr5.workers.dev'

6. THREE RENDERING PROBLEMS A REDESIGN MUST SOLVE
-------------------------------------------------
These are real, verified, and not cosmetic preferences.

(a) Wide tables break on mobile.
    The post contains 2 markdown tables; the important one is 7 columns
    (label / threshold / precision / recall / F1 / AP / test positives).
    global.css sets `table { width: 100% }` and there is NO horizontal
    overflow wrapper anywhere. On a phone the table is crushed. Those tables
    are the centrepiece of the post, so this matters.
    Fix: wrap tables in a container with overflow-x: auto, and use
    font-variant-numeric: tabular-nums with right-aligned numeric columns.

(b) Code blocks are dark islands on a white page.
    Shiki is configured with the "github-dark" theme, so every code block
    renders on #24292e inside an otherwise white layout. Either commit to a
    light Shiki theme, or commit to a dark page.

(c) There is no dark mode at all, and the charts are white-background PNGs.
    Zero occurrences of prefers-color-scheme or data-theme in the codebase.
    The four charts in public/jigsaw/ are matplotlib exports with opaque white
    backgrounds (e.g. pr_baseline.png is 1522x756, eda_cooccurrence.png is
    1463x532, both RGBA). A naive dark theme leaves four glaring white
    rectangles. Do NOT solve this with a CSS invert filter — it wrecks the
    colour-coded lines in the PR curves and the co-occurrence heatmap.
    Better: give figures an explicit light "plate" background with padding and
    a caption, so a white chart reads as an intentional inset in dark mode.
    Best long-term: re-export the charts from the source repo with a
    transparent background and theme-aware stroke colours.


7. CONTENT
----------
Projects page — 4 entries, all public repos. Data lives in a `projects` array
at the top of src/pages/projects.astro; each has title, blurb, detail, stack[],
links[].
  1. Multi-label content classification — DistilBERT on the Kaggle Jigsaw
     toxic-comment data. macro-F1 0.6836 with per-label calibrated thresholds.
     The hook: a model that predicts nothing scores 89.83% accuracy at
     macro-F1 0.0.
  2. JobHunter — finds openings on public ATS boards, scores them, exports a
     ranked sheet. Rate-limited, robots.txt-respecting, draft-only outreach.
  3. RAG Q&A over industrial safety documents — cosine baseline plus a hybrid
     BM25 + vector reranker over 20 PDFs, behind a REST endpoint.
  4. Schema-Aware NL2SQL — fine-tuned T5 with QLoRA, generalises across
     unseen schemas. Web UI + REST API.

Blog — 1 post, ported from the Jigsaw project's README. Long-form, argumentative,
heavy on tables and charts. Structure: results tables, key findings, design
decisions, limitations, how to run it, reproducibility. It leads with the claim
that accuracy is the wrong metric for this problem.

Design implication: the writing is confident and precise, and the content is
metric-heavy. A decorative or playful design would fight it. What flatters this
content is typographic precision, strong number treatment, and figures that
look deliberate.


8. DECISIONS ALREADY MADE — don't undo these
--------------------------------------------
- Static only. No @astrojs/cloudflare, no output: 'server'. A projects page and
  a blog need neither, and adding an adapter only adds complexity.
- Personal repos only on the site. The owner also has work repos under a
  `twofourlabs` org (vanguard, watchdog, ml-training, backend-django-app);
  these are deliberately NOT featured, because they are private employer repos
  whose READMEs describe internal infrastructure.
- The Streamlit demo link is deliberately REMOVED from the projects page. The
  app at multilabel-content-classification.streamlit.app 303s into a ~45-redirect
  loop to a Streamlit login page, so it is not publicly viewable. The line is
  commented out in src/pages/projects.astro, ready to restore if that app is
  ever made public.
- BaseHead.astro's OG image is conditional. The template shipped a stock
  Astro-branded photo as a site-wide og:image fallback; that asset was deleted,
  so og:image is now only emitted when a page actually has an image, and
  twitter:card downgrades from summary_large_image to summary accordingly.
  BlogPost.astro passes heroImage through to BaseHead (the template didn't).
- Post images referenced from markdown live in public/ and use absolute paths
  (/jigsaw/chart.png). Relative paths would 404. heroImage is the exception —
  it must be under src/assets/ so Astro can optimise it.


9. OPEN / NOT DONE
------------------
- The visual redesign. Nothing has been done here; the site is still on the
  template's styling. This is the reason for this document.
- Four design directions were sketched but NOT chosen: (1) terminal / lab
  notebook, dark-first with mono accents and large tabular numerals;
  (2) editorial / research paper, serif display with numbered figures;
  (3) Swiss / brutalist grid, oversized type and hard rules; (4) polished
  modern portfolio with cards and motion. Directions 1 and 3 fit the
  metric-heavy content best. Direction 4 is the safest and least distinctive.
- GitHub profile "website" field is still empty; it should point at the live URL.
- No custom domain. If one is added, `site` in astro.config.mjs must be updated
  to match (see section 3).
- No OG image generation, so shared links have no preview image except on the
  one blog post.
- No table of contents on the long post, which would help — it is long.
- wrangler warns that `workers_dev` and `preview_urls` are absent from
  wrangler.jsonc and so default to enabled. That is the desired behaviour;
  setting them explicitly would only silence the warning.


10. VERIFYING A CHANGE
----------------------
  npm run build            # must exit 0
  npm run preview          # this is what Cloudflare serves

After any change to `site` or the deployed URL, check the generated absolute
URLs — this is the failure mode that hides behind a green build:
  grep -o '<link>[^<]*</link>' dist/rss.xml | head -2
  grep -oE '<link rel="canonical" href="[^"]*"' dist/index.html
  grep -o '<loc>[^<]*</loc>' dist/sitemap-0.xml

Live smoke test:
  BASE=https://srijan-ratrey.sr5.workers.dev
  for p in / /projects /blog/ /about /blog/multi-label-content-classification/ \
           /rss.xml /sitemap-index.xml; do
    echo "$(curl -s -o /dev/null -w '%{http_code}' -L "$BASE$p")  $p"
  done
  curl -s -o /dev/null -w '%{http_code}\n' "$BASE/no-such-page"   # expect 404

Note: /blog returns 307 to /blog/. That is normal Astro trailing-slash
behaviour on Workers, not a bug. Also, immediately after a deploy some assets
can 404 for a few seconds while they propagate — retry before investigating.
